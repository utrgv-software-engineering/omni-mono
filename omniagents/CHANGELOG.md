## [Unreleased]

### Added
- `process` sandbox backend (`omniagents.core.sandbox.process_extended`): a unix_local-shaped client whose every exec — batched execs, PTY shells, and the exec-based file ops — is wrapped in the standalone `omni-sandbox` binary (`omni-sandbox exec --workspace <manifest root> [--ro-bind]... [--rw-bind]... [--net] [--protect]... -- <command>`), giving platform-native process isolation (Linux bwrap+seccomp, macOS seatbelt, Windows AppContainer) without a container engine. Profile schema under `sandbox.client`: `type: process`, optional `binary` (explicit path), `ro_binds`/`rw_binds` (extra mounts), `network: none|unrestricted` (`unrestricted` → `--net`; default blocked), `protected_subpaths` (one `--protect` per entry; omitted → the binary's `.git`/`.env`/`.codex` defaults). Binary discovery at construction time, fail closed: explicit `binary` key → `OMNI_SANDBOX_BIN` env var → `PATH`, with a missing binary raising immediately and naming the install options. Network is all-or-nothing by design: a profile demanding a `network_allow` host allowlist fails closed at construction (mirroring omni-code's governance message shape) because the process sandbox cannot enforce host-level egress filtering — use a container backend for allowlisting. The client mixes in `LifecycleSessionClientMixin` like the other extended clients, so pause/unpause are cleanly reported unsupported by the lifecycle proxies; `ExtendedUnixLocalSandboxClient` gains a `_make_inner_session` seam the process client overrides to stamp the wrapper config on its sessions.
- Project-aware ephemeral runs: `omniagents.core.runtime.run_project_agent_once(agent_key, prompt, ...)` resolves `agents/<agent_key>/agent.yml` through a project manifest (explicit `project_path=`, else the installed product's manifest) and delegates to `run_agent_once`, absorbing the spec-level overrides every product utility-runner re-implemented — `model_settings` stamped on the loaded spec, `instructions` replacing the spec's system prompt for prompts whose source of truth lives in code, and an optional `runtime=` dict turned into an SDK provider via `provider_from_runtime` when no explicit `model_provider`/`env_overrides` are passed (products with provider policy of their own keep resolving those themselves). Resolution is a light manifest read (`paths.agents`, default `agents`; first hit wins across multiple dirs), exposed as `resolve_project_agent_yaml`. To make the default manifest discoverable, `ProductInfo` gains a `manifest_path` field stamped by `load_product_info`/`bootstrap_product` and by `load_project`'s implicit identity install; hand-built infos keep `None`. omni-code's `run_utility_agent` shrinks to a thin delegate.
- Builtin instruction fragments: the framework now ships generic agent-harness instruction fragments as data files under `omniagents/builtin/instructions/` (`personality.md`, `proactiveness.md`, `agents_md_spec.md`, `task_execution.md` — the last parameterized by `task_execution_agent_descriptor`, defaulting to "agent"), lifted from omni-code's `agents/_shared/`. `instruction_search_paths` appends the builtin directory *last*, so a bare `{% include "proactiveness.md" %}` falls through to the builtin only when no project fragment of that name exists — project fragments shadow builtins by name, mirroring builtin-capability/agent precedence. The include loader additionally mounts the builtin directory under the explicit `builtin/` prefix (`{% include "builtin/task_execution.md" %}`), which bypasses shadowing — the escape hatch that lets a project fragment extend its builtin namesake (include + delta) without recursing into itself. `builtin_instruction_fragments_dir()` exposes the location; `InstructionIncludeNotFoundError` now lists the builtin directory among the searched paths.
- Process-global serve-session state (`omniagents.core.runtime.serve_state`), lifted wholesale from omni-code's `agent_workspace_state`: the serve host publishes the running session's wiring — `manifest_root`, the parsed launcher `--source` descriptors (raw dicts preserved for UI callers, plus a typed `SourceDescriptor` view via `get_source_descriptors()` with `kind`/`mount_name`/`path`/`repo_url`/`ref`, `is_local`/`is_git`/`local_path()` helpers, and `from_dict`/`to_dict` round-trip of the wire protocol), the resolved `ProjectContext`, the sandbox-attached orchestrator `AgentSpec`, the live `SandboxSession`, the discard-snapshot-on-exit flag, and the sandbox-profile `SwitchContext` — and every other consumer (server functions, worker spec loaders, skill-root resolution, context factories) reads it without weaving references through call sites. All slots default to absent so non-serve entry points behave standalone; `reset()` restores that for tests.
- The `workspace_info` provider seams (`set_workspace_sources_provider` / `set_manifest_root_provider` / `set_sandbox_session_provider`) now DEFAULT to reading the published serve-session state — an explicitly-installed provider still wins. A product whose serve host publishes into `serve_state` no longer installs any of the three providers.
- Skill-root resolution is now derived, not product-installed: without a `set_skill_roots_provider` install, `skill_roots(workspace_root)` resolves `<workspace>/.{product slug}/skills`, then each published workspace source's `skills/` directory (`source_skill_roots` — mount-name resolution against the serve session's manifest root, host-path fallback when no sandbox session is live, order-preserving dedupe), then `<product config dir>/skills` — so a product with a `product:` section in project.yml gets its conventional layout (omni-code: `.omni_code/skills` + `~/.config/omni_code/skills`) with no code. The previous default (`.omniagents/skills` only, empty without a workspace root) is subsumed: the framework identity derives the same dot-dir, and the invocation directory (`$PWD`) is the fallback base. `default_skill_roots`, `source_skill_roots`, and `dedupe_skill_roots` are exported from `omniagents.core.skills`.
- Serve-session harness (`omniagents.core.runtime.serve_harness`), lifted from omni-code's `serve_cli.py`: the generic core of "serve an agent against a profile-resolved sandbox session". `bring_up_session` builds the sandbox client/manifest from a `ResolvedProfile` + `--source` descriptors (per-source seed entries, `run_as` user pre-declaration), creates-or-resumes the session (3-tier docker resume: `reused` warm reattach / `rehydrated` from the snapshot tar / `fresh`, reported as a tier tag), scrubs unsafe symlinks from the snapshot tar before hydrate (`_scrub_session_snapshot`), applies the profile's idle-pause threshold, configures boot-time git/CLI credentials (`gh` / `az devops`, token via env-var name only), runs profile init commands as root, and starts services reuse-aware (adopts an instance already holding its port on a warm container) with exposed-port URL resolution. `perform_switch` is the full in-place profile-switch orchestration (lock, run-quiesce, workspace carry off noop-snapshot backends, teardown, bring-up, spec/terminal re-wire, `ui.sandbox.*` broadcasts, rollback-to-previous on failure) — install it via the existing `sandbox_lifecycle.set_switch_executor` seam. `teardown_session` stops PTYs, defensively unpauses, persists (or discards) the workspace snapshot via `session.stop()`, and closes; `None`-safe and swallow-all so shutdown never wedges. `bring_up_host_target` covers the no-sandbox `host` execution target (process-default `HostWorkspace` with profile-gated `confine`). The harness publishes the serve-state it derives itself (manifest root, sources, live session, orchestrator spec on switch/rollback); products publish only what it cannot know (project context, boot-time orchestrator spec, the `SwitchContext`). Product knobs default to the omni-code values they were lifted with: `NOOP_SNAPSHOT_CLIENT_TYPES` (`unix_local`/`host_bridge` skip lifecycle snapshots), `DEFAULT_SERVICE_URL_SUFFIXES` (a `vnc` service gets the noVNC client page), and the new `SwitchContext.profile_resolver` field — the product's layered profile resolver, used by switch/rollback so product profile layers apply mid-session too (framework resolver is the fallback). omni-code's `serve_cli.py` shrinks to product wiring (CLI surface, spec loading, FastAPI app, readiness payload) over the harness.


## [0.7.21] - 2026-07-18

### Added
- Product CLI host (`omniagents.product_cli`), driven by project.yml: `product_main(project_path, argv=None) -> int` collapses a product's hand-rolled CLI dispatcher to a ~5-line console script — if the base command is `omni`, the update command is `omni update`, all from configuration. It bootstraps the product identity first (`bootstrap_product`), then mounts the reserved subcommands from convention: `model`/`provider` (framework model CLI on the installed process-wide model store, with a generic product-config-dir store as fallback), `auth` (platform login/logout/status + the `auth codex` passthrough), `update` (mounted ONLY when the manifest declares a `product.update:` block; `UpdaterConfig.from_product`), and `sessions` (framework sessions CLI pinned to the product slug as project and the manifest's `agents.entrypoint` as default agent — exported as `run_product_sessions_command` so product overrides can delegate). Everything else falls through to `omniagents run --project <manifest> --mode <cli.default_mode>` (default `ink`) with args passed through, a leading `--` forcing prompt mode even for reserved words, and the update notice printed on the fallthrough path only. Product-specific behavior plugs in via a manifest-declared extension module — `cli: {default_mode: ..., extensions: my_product.cli_extensions}` — which may define `PREFLIGHT: list[Callable[[list[str]], list[str] | None]]` (argv hooks run in order before any dispatch; may veto/exec or rewrite argv — governance sandbox re-exec, first-run wizards, embedded-mode interception) and `COMMANDS: dict[str, Callable[[list[str]], int | None]]` (extra subcommands or overrides of reserved ones). Dispatch precedence: PREFLIGHT → COMMANDS (product) → reserved (framework) → fallthrough run. `dispatches_to_command(argv, extra_commands=...)` is the public gate preflights use to run only on agent-run invocations; `load_product_cli_config` is the light `cli:` parse (unknown-key typo protection, like `product:`).

## [## [Unreleased]] - 2026-07-18

### Added
- Product identity descriptor (`omniagents.core.product`), convention over configuration: a top-level `product:` section in project.yml (`name`, `prog`, `label`, `slug`, `config_dir`, `windows_config_dir`, `env_prefix`, and an optional `update:` block with `index_url`/`package`/`command_hint`) declares once the identity constants downstream products used to hand to each framework subsystem one at a time; a minimal `product: {slug: x}` derives everything else. Parsed into a frozen `ProductInfo` (with `ProductUpdateInfo` and a `config_dir()` path helper), installed process-wide via `set_product_info()` / read via `product_info()` (default: the framework's own `omniagents` identity). `load_product_info(project_path)` is a light parse — a plain YAML read of the `product:` key, no project resolution — and `bootstrap_product(project_path)` (load + explicit set) is the single call a product's cli.py makes first. `load_project` installs the manifest's `product:` section automatically, but an explicit `set_product_info`/`bootstrap_product` always wins and is never clobbered.
- Every subsystem that required identity arguments now defaults them from the installed product identity, with explicit arguments still winning (full backward compatibility): `run_model_command`/`run_provider_command` (`prog=None` → `product_info().prog`, `product_label` → `.label`), `run_codex_auth_command`/`run_platform_auth_command` (`prog=None` → `.prog`), `product_config_dir()` (argless form → the product's config-dir/windows names), the platform client (`get_product_slug()` and the `platform.json` store dir fall back to product identity when not explicitly bound), the codex token store (same fallback, after `OMNIAGENTS_CODEX_HOME`), `UpdaterConfig.from_product(info=None)` + `run_update_command(config=None)` (built from the `product.update:` block — cache dir from the product config dir, env prefix from the product; clear `ValueError` when the product declares no `update:` block), and `resolve_profile(config_dir=None)` (user sandbox-profile layers under the product config dir).
- Builtin agents: the framework now ships stock sub-agent specs under `omniagents/builtin/agents/<key>/agent.yml`, merged into every project's agent registry after project agent discovery — mirroring builtin-capability precedence (a project `agents/<key>/` definition shadows the builtin by name; `agents.include`/`exclude` globs apply, so `exclude: ["explorer"]` opts out). First builtin agent: `explorer`, a read-only workspace exploration sub-agent (capabilities `filesystem_readonly` + `shell_readonly` + `notebook_readonly`, low reasoning effort, parallel tool calls, headless), lifted from omni-code and domain-neutralized. It declares no model or `model_config_resolver` — it inherits the orchestrator's resolved model — so products only shadow it when they want different model routing.
- Builtin `exploration` capability pack: exposes the builtin `explorer` as an `explore` agent tool (`max_turns: 50`, no approval) with delegation guidance — use `explore` for broad workspace questions, re-read key files after it returns. Products get the pack by listing `capabilities: [exploration]` on an agent; shadowing `explorer` re-points the pack's tool at the product's own definition.
- Builtin `workspace_info` capability pack (`fs_get_cwd`, `fs_get_workspace_root`, `fs_get_home`, `fs_list_dir`, `fs_get_sources`), lifted from omni-code. Fixes an inverted dependency: the web backend's workspace picker feature-detects these names (`App.tsx` / `WorkspacePicker.tsx`) but only omni-code defined them — the contract and implementation now live together. `fs_list_dir` is sandbox-aware (browses the container filesystem via `SandboxWorkspace`, clamped to the manifest root) when an embedder installs providers via the new `omniagents.core.runtime.workspace_info` seams: `set_workspace_sources_provider` (defaults to no sources), `set_manifest_root_provider`, and `set_sandbox_session_provider` — standalone servers fall back to the host filesystem.
- Builtin `terminal` capability pack (`terminal.create` / `terminal.close`), lifted from omni-code — the server-function half of the terminal contract the framework already shipped (`TerminalManager`, `/ws/terminal`, PTY backends). Dual binding modes: a sandboxing embedder installs a configured `TerminalManager` on the service (`service.terminal_manager`) whose defaults win; standalone servers lazily fall back to a host-pty manager with cwd resolved from the session context. `attach_terminal_manager` / `terminal_supported` helpers exported from `omniagents.builtin.server_functions.terminal`.
- Note: omni-code's `session_ensure` server function is intentionally NOT lifted — it only proxied the framework's own builtin `session.ensure` (registered by `AgentService`), which clients (including the web UI, which never calls `session_ensure`) should use directly. The omni-code shim dies downstream.
- Shared instruction fragments: agent instruction templates (Jinja2) now support `{% include %}`. The render environment gets a `ChoiceLoader` over ordered search paths — the instructions file's own directory, its `_shared/` subdirectory, the sibling `_shared/` directory (`agents/_shared/` in the strict layout), plus optional `paths.instruction_fragments` dirs from project.yml. Wired through `AgentSpec.instructions_search_paths` into the agent builder and the realtime (voice) session, so text and voice agents can share verbatim instruction blocks instead of drifting copies. Missing includes raise `InstructionIncludeNotFoundError` naming the searched directories; templates without includes render byte-identically to before (regression-tested).
- Generic pipx self-updater (`omniagents.core.updater`), lifted from omni-code: products describe themselves with an `UpdaterConfig` (simple-index URL, pipx package name, cache dir, env-var prefix, plus optional update-command hint and pip extra-index override) and reuse `check_for_update` (PEP-503 simple-index version scrape), `maybe_print_update_notice` (throttled `update.json`-cached startup notice with failure-retry backoff, honoring `<PREFIX>_UPDATE_CHECK` and `<PREFIX>_UPDATE_CHECK_INTERVAL_SECONDS`), and `run_update_command(argv, config=..., prog=...)` — the check/confirm/`pipx upgrade` CLI flow, parameterized by program name like `run_codex_auth_command` / `run_model_command`.
- Management-plane auth client (`omniagents.core.providers.platform.client`), lifted from omni-code: device-code sign-in (`device_code_login`), owner-only `platform.json` credential store (`load_credentials` / `save_credentials` / `clear_credentials`), env-then-file URL/token resolution (`get_platform_url` / `get_access_token` / `resolve_platform`), and `refresh_access_token`. Products bind it to their own conventions with `set_credential_store_dir` / `set_product_slug` (mirroring the codex token-store binding) instead of shipping their own copy.
- `run_platform_auth_command(argv, prog=..., slug=..., config_dir=...)` — public platform auth CLI flow (login / logout / status), the management-plane sibling of `run_codex_auth_command`; also wired up as `omniagents auth {login,logout,status}`.
- One platform policy client: `client.fetch_policy` serves both the user scope (`GET /api/v1/policy/{slug}`) and the session scope (`GET /api/v1/sessions/{id}/policy`), with a single refresh-on-401 retry in both. `PlatformPolicyFetcher.fetch` now delegates to it (session-scoped fetches gain the 401 retry), and platform bootstrap's `_detect_platform` delegates its env-then-stored priority chain to `client.resolve_platform` (falling back to the client's credential store when no product loader is installed).
- `MultiSourceWorktreeIsolation` (`omniagents.core.workers`): worktree isolation for workspaces assembled from several sources, lifted from omni-code. One git worktree (branch `worker/<parent>-worker-<id>/<name>`) or `cp -a` copy per source, mounted by name under a shared worker root in the framework scratch area; transactional creation (partial failures roll back worktrees, branches, and the worker root) and metadata-driven cleanup. Parameterized by a `SourcesProvider` returning `WorkerSource(name, host_path, git)` descriptors — no product state in the framework — and degrades to plain single-repo `WorktreeIsolation` when the provider yields no sources, so products register it under `name="worktree"` as a drop-in replacement.
- Framework-owned default worker instructions: the generic worker system prompt (stay-focused, parallel tool calls, absolute paths, private task-list scoping, when-stuck/blocker protocol, structured output format) now ships as `DEFAULT_WORKER_INSTRUCTIONS` / `worker_instructions.md` (path via `default_worker_instructions_path()`), lifted from omni-code's worker agent and domain-neutralized. `WorkerManager` applies it to every spawned worker spec that carries no instructions of its own (`apply_default_worker_instructions`, same seam as the safety defaulting); products layer their delta via their own `instructions_file` or the template's `additional_instructions` / `agents_md_block` hooks.
- `make_project_worker_spec_loader` (`omniagents.core.workers`): builds a `WorkerDefaults.spec_loader` bound to a project registry — worker spec via `build_spec_from_project` (full capability/tool/guardrails registries), orchestrator sandbox attachment forwarding, resolved model/model-settings stamping, `resolve_default_model_config` exposure — parameterized by `project_provider`, `agent_key`, `project_slug`, `model_resolver`, and `orchestrator_spec_provider`, so a product's worker wiring shrinks to naming its providers.
- `sessions summarize <session_id>` subcommand on the framework sessions CLI (`omniagents.core.session.cli`): history tail-trim (`--tail`, default 200), transcript extraction, shrink-on-context-error summarization via `summarize_with_window_shrink`, and a JSON envelope on stdout. Completes the recap/compaction symmetry for offline session summarization (`omniagents.core.session.summarize`): products install a summarizer with `set_session_summarizer` (their session-summarizer agent + model resolution; the callable receives `(prompt, *, model, project, agent, session_id)`), and `DEFAULT_SESSION_SUMMARY_INSTRUCTIONS` is a ready-made summarizer system prompt (lifted from omni-code's session_summarizer agent and domain-neutralized). The envelope's content keys are a parameter of the flow (`envelope=` on `summarize_session`, `args.summary_envelope` on the CLI mount) with a neutral default (`DEFAULT_SESSION_ENVELOPE`), so products keep their domain-flavored keys.
- Model runtime/provider plumbing beside `ModelConfigStore` (`omniagents.core.models`), lifted from omni-code: `resolve_model_runtime` (ref → `(model_name, runtime)` with optional prefix normalization) and `resolve_service_model_runtime` (utility-run preference order: session active model → service spec model → raw session `model_config`), both taking an explicit `store=` or the process-wide registry installed via `set_model_store`; `normalize_model_name` (runtime-side counterpart of the store's ref parsing — strips non-`openai/`/`litellm/` provider prefixes, keeps LiteLLM ids whole); and `provider_from_runtime`, the runtime-dict → SDK model-provider adapter over `run_options.build_model_provider` that adds the credential policy the plain builder does not apply (litellm API-key env overrides, env-var credential fallback, "no credential against a real OpenAI/Azure endpoint → no provider", dummy key for local endpoints).
- Governed model config producer (`omniagents.core.models.governed`): `write_governed_config` / `load_governed_config` / `governed_config_path` own the `models.governed.json` artifact next to `models.json` — `_governed`/`_allow_user_models` markers, per-provider `_governed` stamping, merge-base vs replace semantics read back by the store's layered merge, 0600 permissions — parameterized by config dir. Products keep only the policy-key extraction that feeds it.
- `container_runtime()` / `container_runtime_available()` (`omniagents.core.sandbox.container_runtime`): docker/podman CLI selection honoring `OMNIAGENTS_CONTAINER_RUNTIME`, with an `env_vars` seam so products can put their own operator knob first (omni-code: `OMNI_CONTAINER_RUNTIME`). CLI-binary concept only — the docker sandbox backend keeps talking to the engine API via the docker SDK (`DOCKER_HOST` covers Podman's docker-compatible socket there).
- `resolve_prompt_file(candidates, fallback, max_bytes=...)` (`omniagents.core.utils.prompt_files`): user-overridable prompt-file resolution — first non-empty candidate (workspace file, then user-config file), size-capped and error-tolerant, else the builtin fallback text. Lifted from omni-code's loop-prompt resolution; pairs with the `set_loop_default_prompt_resolver` seam.
- `UserMcpFixtureStager` (`omniagents.core.eval.mcp_fixture`): per-scenario user-MCP fixture staging for eval environments — isolated `XDG_CONFIG_HOME` inside the scenario temp dir, fixture file/tree copies, generated `<product>/mcp.json`, and an `env_vars()` contribution for `get_env_vars()`. Lifted from omni-code's `WorkspaceEvalEnvironment` minus its cross-scenario lock, which the runner fix below makes unnecessary.
- The builtin `shell` / `shell_readonly` packs now steer discovery toward the shell over the filesystem discovery tools when piping/chaining (`| head`, `| xargs`) helps — restoring a nuance from omni-code's retired filesystem-pack override.
- The environment-backed eval runner (`run_scenario`) now applies environment-declared env vars (`get_env_vars()`) *before* loading the agent spec, not after. Spec loading reads the process env — notably `XDG_CONFIG_HOME` for `allow_user_mcp_servers` discovery — so environments staging per-scenario config previously had to mutate `os.environ` in `setup()` under a self-managed lock. With no awaits between application and spec load, each concurrent scenario's spec load reads its own values.

- Builtin `filesystem_readonly` and `shell_readonly` capability packs — read-only surfaces for research/explorer subagents.
- Builtin `slash` capability pack with a `dispatch` tool that executes commands from the new process-wide default `SlashCommandRegistry` (`register_slash_command` / `default_slash_registry` in `omniagents.core.tools`).
- Checkpoint compaction is a first-class concept in `omniagents.core.runtime.compaction`: `run_checkpoint_compaction` (window since last `context_summary` marker, shrink-on-context-error retry via `summarize_with_window_shrink`, resume-protocol summary item with a default envelope), plus `make_auto_compact_error_hook` for reactive on-context-error compaction. Products supply only the summarizer (their compactor agent + model resolution). The session manager's marker windowing now delegates here — the marker is the checkpoint contract, not a legacy artifact.
- `PlatformCredentialProvider` reworked around its real caller: sync core with async wrappers, `get_credential_by_ref_sync` resolving policy `{session_id}` refs, uniform `None`-on-failure contract (was ad-hoc error dicts), and `ensure_platform_session` for local (launcher-less) session bootstrap, agent-parameterized.
- `set_platform_credentials_loader`: platform bootstrap no longer hardcodes any product config path — products install a loader for their stored credentials; without one, detection is env-var-only.
- `omniagents.testing`: reusable pytest fixtures (`invoke_tool`, `test_event_loop`, autouse permissive workspace) for tool test suites — import them into a `conftest.py` to keep directory scoping.
- `instructions_append:` on `extends:` capability overrides — append product guidance to the base pack's instructions instead of copying the whole text to add a line (mutually exclusive with `instructions:`).
- `IdleTrigger` / `IdleTriggerScheduler` in `omniagents.core.autonomy.idle`: fire product actions (e.g. an auto-recap) when a session goes idle — idle-threshold, min-turns, and never-twice-in-a-row rules generalized from omni-code's recap watcher.
- Version management system with `_version.py`
- CLI `--version` flag support
- Automated versioning workflow with bump2version
